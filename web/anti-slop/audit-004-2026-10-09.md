# Novelread UI audit 004

Date: 2026-10-09  
Mode: After (session override)  
Scope: Static comparison of the current homepage, novel detail, and author profile against the saved Story Cinema concepts and `ดีไซต์.md`.

## Direction read

Reading this as: a Thai novel discovery and reading product for readers and writers, using the approved Story Cinema direction with deep navy, ivory text, warm gold actions, and artwork-led hierarchy.

## Findings

21. **LOW - R-31:** The desktop header does not match the approved homepage composition: category navigation is a direct link and the account trigger is a generic icon-and-text button, while the mockup shows a category dropdown and a profile/avatar cue. See `web/components/navigation/site-header.tsx` and `design/references/home-approved-c.png`.

22. **LOW - R-20:** Homepage sections reuse the same novel set and repeat artwork: the first five novels become the hero slides, the full list becomes “อัปเดตล่าสุด”, category browsing selects from that same list, and completed novels are a subset. Hero artwork is selected by category, so novels in one category can share the same scene. This weakens the distinct browsing roles and image variety shown in the approved concept. See `web/app/page.tsx`, `web/components/novel/spotlight-carousel.tsx`, and `web/lib/presentation/novel-art.ts`. The backend does sort the books by `updated DESC`, so the “latest” ordering itself is supported.

23. **MEDIUM - R-03:** On mobile, the novel-detail hero still hides its summary and places “เริ่มอ่านตอนแรก” and “ดูสารบัญ” side by side. The earlier `display: none` rule remains active because the later mobile override changes font size and line clamping but does not restore `display`; the proposal shows the summary and vertically stacked full-width actions. See `web/app/globals.css` mobile rules and `web/app/novel/[id]/[slug]/page.tsx`.

## Follow-up: approved fixes

The user approved findings 21–23 by asking to make the UI match the agreed design. All three were addressed:

- 21: desktop navigation now offers a category dropdown, and the account menu has a circular profile cue.
- 22: homepage hero slides use each novel's actual cover (with title/category fallback artwork); hero, latest, genre browsing, and completed sections draw from separate novel IDs. Latest items retain the API's `updated DESC` order.
- 23: novel summaries remain visible on mobile and the reading/catalog actions stack as full-width controls.

Verification: `npm run typecheck` passed; `npm run build` passed. Browser navigation remained blocked by the in-app browser policy, so responsive appearance and interactions were not visually verified here.

## Context and limits

- `design/references/home-approved-c.png` is marked approved in `ดีไซต์.md`. The detail and author images are still marked as proposals there, so they confirm the Story Cinema direction but are not recorded as approved page layouts.
- The author API currently provides an ID, name, and works, but no author photo or biography (`web/lib/api/novels.ts`). The generic banner and fallback icon remain in place as specified in the design plan.
