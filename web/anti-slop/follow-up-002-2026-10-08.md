# Anti-slop follow-up 002

Date: 2026-10-08  
Approved scope: findings 16–18 from `audit-002-2026-10-08.md`, interpreted with the user's follow-up that the UI felt over-boxed and rigid.

## Implemented

- Replaced the homepage's long uniform card grids with latest and category rails. Previous/next buttons move one cover per click; there is no autoplay. The rail keeps the real latest/category data and does not imply editorial selection.
- Removed the surrounding card border, fill, and shadow from homepage and shelf story cards. The cover remains the focal point; category, status, and chapter details use lighter text treatment.
- Reworked text-only cover fallbacks to use quiet paper tones and centered story typography, removing the repeated gradient and orbit lines. Existing story data and real cover URLs are preserved; no new visual assets were created.
- Changed bookshelf tabs to a text-and-underline treatment and made reading progress thinner, reducing the number of nested outlines on mobile.
- Updated the visual rationale, responsive layout, and motion behavior in `UI-REDESIGN.md`.

## Verification

- `npm run build`: PASS (Next.js 16.3.8). The initial sandboxed run was denied by Windows path access; the approved rerun succeeded.
- Live UI checked at 375×812, 390×844, 768×900, and 1440×960. No visible page overflow at these widths; homepage rails show a partial next cover on phones and four/six covers at tablet/desktop sizes.
- Clicked a homepage next-cover control and verified the track advanced one card and enabled the previous control.
- Opened and dismissed both search selectors; submitted a no-result query and saw the no-results state.
- Toggled the bookshelf tab and opened/dismissed the mobile navigation with Escape.
- Contrast samples for new muted text on white and placeholder-cover colors are at least 4.51:1.

## Remaining content constraint

Local homepage and shelf data still contain explicitly named test novels, and the shown stories do not have uploaded covers. This pass keeps those records intact and uses honest typographic placeholders; replacing them with new cover art would require a separate explicit request under R-23.
